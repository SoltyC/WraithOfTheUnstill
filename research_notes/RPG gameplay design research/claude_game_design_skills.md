# Claude / Claude Code skills and agent packs for game design

## What exists (Agent Skills, plugins, subagents for game design)

### Takeaway
Several community packs exist; none are official. The most substantive design content is in saschb2b/skills `game-design` and Donchitos/Claude-Code-Game-Studios (agents/skills with named frameworks). gamedev-skills/awesome-gamedev-agent-skills has an `rpg` skill plus `level-design`, `game-feel`, `dialogue-systems`, and a web-engines bundle. Anthropic's own repo has no game-design skill.

### Inferences
- Nothing found specializes in open-world action RPG design (quest structure, boss design, combat tuning, exploration pacing). The RPG-specific material is implementation-oriented.
- Third-party skills inject generic textbook frameworks; value is mostly as checklists/critique prompts, since the model already knows MDA/flow.
- Star counts (esp. CCGS) are partly hype; the project's own README downplays process weight.

## Recommendation and custom skill contents

### Takeaway
Do not install CCGS wholesale (Godot/Unity/Unreal-oriented, heavy, shared context). Worth a read-then-adapt: saschb2b `game-design` (best design content; borrow critique smells, pillar-gating, loop-stack, mechanic spec) and CCGS `game-designer` agent + `/balance-check` + `/playtest-report` (steal structure). Build a small custom project skill.

### Cited Findings
- Anthropic docs: SKILL.md needs name+description (description drives triggering); long content goes into references/, assets/, scripts/ — [Claude docs](https://www.claude.com/docs/skills/how-to)
- saschb2b guidance keeps SKILL.md under ~100 lines with sibling reference files — [repo](https://github.com/saschb2b/skills)

### Inferences
Suggested custom `wraith-design` skill (SKILL.md short, references/ split):
1. Pillars + x-statement, each pillar naming what it rejects; feature gate: must serve a pillar, feed a loop layer, survive critique smells (from saschb2b pattern).
2. Loop stack: 30s combat/traversal, 5-15min encounter/quest, session, long-term progression; every mechanic ties to a loop.
3. Combat/boss: telegraph honesty, defender-gets-a-verb, phase structure, TTK/DPS targets table, tuning knobs in data files (Babylon/JSON), attack timing frames.
4. Game feel: hit-stop, shake, camera, input latency budgets, feedback < 0.5s; tuned against 1440p/60 target.
5. Quest/level: open-world pacing (landmark/POI density, sightlines, intensity curve), quest state model, reward cadence.
6. RPG economy: faucets/sinks, XP curve dead zones, power spikes, loot pity; balance-check procedure with explicit NOT ASSESSED rule.
7. Playtesting: checklist plus the project's existing ?bot=1 bot harness to produce findings reports (per CCGS /playtest-report structure); critique smells list.
8. Project-specific: current build state, known issues, Babylon perf constraints.
